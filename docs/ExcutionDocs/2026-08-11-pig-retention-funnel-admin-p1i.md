# 小猪周回顾管理员漏斗视图 P1-I 执行记录

## 1. 阶段结论

P1-I 在现有 Web 管理后台增加周回顾留存漏斗视图，直接消费 P1-H 的管理员聚合接口。默认查询小猪最近 12 周，可切换小猫、小狗以及 4、8、12、26、52 周范围。

本阶段只展示按周聚合的去重人数和转化率，不增加用户级明细、下钻、导出或新的后端接口，也不改变原有用户管理流程。

## 2. 改动范围

- `frontend/src/components/AdminWeeklyReviewFunnel.tsx`：独立管理筛选、加载、错误、空数据和表格展示。
- `frontend/src/pages/Admin.tsx`：在既有用户管理区域之后挂载漏斗组件。
- `frontend/src/services/index.ts`：为 `adminApi` 增加聚合漏斗查询方法。
- `frontend/src/types/index.ts`：增加与后端响应一一对应的类型。
- `frontend/src/lib/retention.ts`：提供周区间和转化率的纯格式化函数。
- `frontend/scripts/test.mjs`、`frontend/tsconfig.test.json`：把纯格式化边界纳入现有轻量测试。

未修改路由、认证 store、全局样式、桌面端、后端或数据库。

## 3. 展示口径

每一周展示：

- 生成去重用户数。
- 展示去重用户数及“生成到展示”转化率。
- 已读去重用户数及“展示到已读”转化率。
- 后续互动去重用户数及“已读到后续”转化率。
- 照料、聊天和提醒三类后续互动人数。

前端不重新排序、不重算漏斗，也不把三个互动分类相加。漏斗闭合和分类并集继续以后端 P1-H 口径为准。

## 4. 状态与交互

- 初次进入自动加载小猪最近 12 周。
- 宠物和周数是查询草稿，只有点击“查询漏斗”后才提交请求。
- 成功结果保存实际响应宠物和成功查询周数，避免筛选草稿改变后误标旧数据。
- 首次加载显示状态占位；无数据返回明确空状态，不当作错误。
- 已有结果刷新时保留旧表并提示“正在刷新”。
- 刷新失败时明确说明当前仍显示上次成功结果，避免把旧数据误认为本次查询结果。

## 5. Review 修复

独立 review 后完成以下修复：

1. 将漏斗追加到现有用户管理区域之后，避免最长 52 周表格拆开原有管理信息流。
2. 为已有结果刷新增加 `role="status"` 状态提示。
3. 为失败后保留的旧结果增加明确语义。
4. 非有限值、负数或大于 1 的异常比率显示 `—`，不伪装为真实 `0%`。
5. 横向滚动表格容器支持键盘聚焦，并保留 caption、行标题和列标题。

## 6. 隐私与权限边界

视图只消费管理员聚合接口，前端不接收或展示用户 ID、用户名、邮箱、原始事件、设备信息或任意单用户轨迹。页面级管理员守卫只负责导航体验，真正的权限边界仍由后端 `get_current_superuser` 保证。

本阶段没有增加更细时间粒度、用户筛选联动、原始事件下钻或数据导出，避免扩大聚合数据的小样本推断风险。

1. 使用管理员账号分别查询小猪、小猫、小狗，核对空数据和有数据状态。
2. 准备包含缺失上游埋点、多类别后续行为的周数据，对照 P1-H 响应逐列核验。
3. 在窄屏和键盘导航下验证横向表格、筛选控件、刷新状态和错误提示。
