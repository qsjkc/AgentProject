# 小猪关系里程碑回礼 P1-J 执行记录

## 1. 阶段结论

P1-J 将小猪从 Lv.2 到 Lv.5 的关系升级改造成可恢复的里程碑回礼。升级事务会立即解锁对应装扮并创建待展示记录；桌宠只在可见、空闲且没有更高优先级交互时领取并播放一次专属庆祝，临时试戴新装扮，完整播放后再确认。

本阶段不新增商店、货币、连续任务、惩罚、下钻或分析埋点，也不改变猫和狗原有的通用升级提示。

## 2. 后端持久化与接口

新增 `pet_relationship_milestones` 表，记录关系、等级、回礼装扮、达成时间、租约和确认时间。数据库约束保证同一关系的同一等级只产生一条里程碑；用户和宠物归属始终通过关系记录校验，不在里程碑中重复保存用户标识。

升级跨过多个等级时，会在关系 XP、等级、阶段、亲密事件和装扮解锁所在的同一事务内逐级创建里程碑。装扮权益在升级时立即生效，不依赖桌面端是否成功展示或确认。

新增接口：

- `POST /api/v1/pets/{pet_type}/relationship/milestones/claim`：使用客户端 UUID 原子领取最早的未确认里程碑，租约为 5 分钟；相同 token 重试会续租；无可领取项返回 204。
- `POST /api/v1/pets/{pet_type}/relationship/milestones/{id}/ack`：确认已完整展示；相同 token 可幂等重试；被其他 token 接管后返回 409；跨用户、跨宠物或不存在时返回 404。

迁移编号为 014，当前 Alembic head 为 014。迁移只创建空表，不回填部署前已经达到 Lv.2–Lv.5 的历史关系，因此只有部署后的新升级会产生回礼；这是为了避免历史用户首次上线时集中收到多段旧回礼。

## 3. 桌面播放状态机

桌面端使用 `claim`、`playing`、`ack_pending` 三个持久状态，并保存 UUID claim token、里程碑和 revision。Electron 主进程对写入和清理执行 revision CAS，登录态切换会清理关系、里程碑和陪伴缓存；渲染进程使用 context epoch 隔离旧用户、旧宠物和晚到异步响应。

新里程碑只在以下条件同时满足时领取和播放：

- 当前是已登录的小猪桌宠，窗口可见；
- 语音空闲，没有拖拽、回弹、照料或临时气泡；
- 动画处于未锁定的 idle；
- 当前关系等级不低于里程碑等级，且回礼装扮已经解锁。

跨设备升级导致本机关系缓存落后时，客户端会先刷新小猪关系；刷新失败或仍不满足条件时释放本地领取状态，让服务端租约自然过期，不让隐藏或过期设备长期占用队首里程碑。

## 4. 庆祝、文案与临时试戴

Lv.2–Lv.5 分别使用睡帽、铃铛、伙伴徽章和星星帽的等级专属中英文回礼文案。庆祝使用锁定的 `level_up` 动画序列，并把 milestone ID 和动画 cycle 绑定，旧动画或无 ID 的完成回调不能误确认新里程碑。

试戴只在当前里程碑播放期间覆盖相同装扮槽位。它不会调用换装接口，不会修改已装备状态、关系缓存或 XP；播放结束或被中断后立即消失。

## 5. 优先级与失败恢复

提醒、语音、拖拽、点击、照料、窗口隐藏和正式换装都可以中断里程碑。中断会把 `playing` 重新持久化为 `claim`，不发送 ACK；下一个安全窗口再播放。照料按钮不会因为 `level_up` 被禁用，提醒仍能抢占锁定动画。

动画完整结束后，客户端先持久化 `ack_pending` 和 `displayed=true`，再请求 ACK：

- 普通网络失败只重试 ACK，不重播动画；
- ACK 409 会保留“本机已经展示”的 tombstone，用新 token 协调服务端状态；重新取得同一项时只 ACK，队首已前进时才处理下一项；
- ACK 404 视为终止的旧上下文并清理，不无限重试；
- 重启时 `playing` 会回到待播，`ack_pending` 只继续确认；
- 损坏或旧版的本地状态会在主进程边界被识别并清理，避免 revision 冲突永久阻塞队列。

陪伴轮询在异步读取每日、每周摘要后会再次核对语音、拖拽、照料、气泡、锁定动画和里程碑播放状态，避免晚到的陪伴文案覆盖正在展示的回礼。

## 6. 一次性语义边界

claim 和 5 分钟租约能保证租约有效期内只有一个持有者；完整播放后先落盘再 ACK，可以在正常网络失败和同机重启下避免重复展示。

视觉副作用与服务端确认无法在客户端崩溃或操作系统长时间挂起的瞬间实现数学意义上的跨设备 exactly-once。如果设备在动画中挂起超过租约，另一设备可能接管，旧设备恢复后仍存在重复边界。因此本阶段承诺的是高概率单次展示、确认后不再下发，以及崩溃边界的 at-least-once；5 分钟租约相对于约 1 秒动画显著缩小了风险，但没有把风险归零。

## 7. Review 修复

独立 review 后完成了以下修复：

1. 由持久 milestone 驱动小猪升级，不再依赖易丢的关系等级快照差异。
2. claim 增加租约、相同 token 续租和条件更新，避免多窗口、多设备同时持有。
3. 新 claim 前增加可见和空闲门禁，避免隐藏或忙碌窗口持续霸占租约。
4. 当前等级判断从严格相等改为大于等于，支持积压的多级回礼按顺序播放。
5. 提醒、语音、拖拽和照料显式中断播放，旧动画回调不能结束当前里程碑。
6. 持久化写入、清理、中断和重启回队都采用并消费 revision CAS 结果；旧 epoch 不覆盖新上下文。
7. ACK 409 使用已展示 tombstone 协调，ACK 404 终止旧上下文，避免重复或永久堵塞。
8. 本机关系缓存低于服务端里程碑等级时先刷新关系，失败则不续租。
9. 通用 API 请求兼容 204 空响应；里程碑 token、顶层与明细一致性和损坏 store 均做校验。
10. 陪伴摘要异步返回后再次检查播放安全状态，避免覆盖里程碑文案。
