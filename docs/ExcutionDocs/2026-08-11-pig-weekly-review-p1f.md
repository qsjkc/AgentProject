# 小猪非签到式周回顾 P1-F 执行记录

## 1. 阶段结论

P1-F 在“今日相处”和重复提醒基础上增加上一完整自然周的陪伴回顾。回顾只使用真实互动、照料、聊天、提醒和亲密度成长事实，不设置连续签到、缺席惩罚、关系下降或负面忙碌反馈。

当前代码、自动化测试、桌面渲染构建和迁移 011 的隔离验证已经完成；尚未进行真实桌面交互验收、现有 PostgreSQL 数据库迁移和生产环境验证。

## 2. 用户体验

- 周回顾统计 `PET_REWARD_TIMEZONE` 下最近一个已经结束的周一至周日。
- 没有有效互动的空白周不展示回顾，也不会产生负面文案。
- 有新回顾时，在小猪下一次正常主动陪伴机会中优先于今日记忆展示。
- 回顾使用简短气泡和开心动作，不新增签到入口、弹窗或打扰式红点。
- 文案优先表达关系升级，其次表达完成提醒、照料、聊天和总体相处次数。
- 展示成功后写入服务端已读回执，同一周默认只展示一次。
- 已读请求失败时不写入本地最近文案去重，保留后续主动陪伴机会重试的能力。

## 3. 统计口径与隐私边界

周回顾返回以下聚合事实：

- 活跃天数和互动总数。
- 获得的亲密度经验。
- 照料、有效聊天、创建提醒和完成提醒次数。
- 周初、周末关系等级，以及跨越的等级数。
- 首次和最后一次互动时间。

服务端继续按用户和宠物类型隔离数据。响应不包含提醒标题、聊天原文、提醒来源文本或其他私密内容。周期提醒自动物化的后续实例不计为用户主动创建提醒，但真实完成的每次实例仍独立计入完成次数。

## 4. 服务端与数据模型

新增接口：

- `GET /api/v1/pets/{pet_type}/weekly-summary`
- `POST /api/v1/pets/{pet_type}/weekly-summary/seen`

`pet_relationships` 新增：

- `last_weekly_review_key`
- `last_weekly_review_seen_at`

迁移 011 负责字段升级和回滚。已读接口只接受当前可用回顾的 `review_key`；过期回顾或空白周返回冲突，避免客户端误标记其他周。

## 8. 下一阶段建议

P1-G 建议进入最小留存埋点：记录周回顾是否生成、是否展示、已读是否成功，以及展示后用户是否继续发生照料、聊天或提醒行为。埋点只保留事件类型、时间、用户与宠物的内部标识和必要聚合字段，不采集聊天原文或提醒标题。

这一阶段应先回答“周回顾是否真的带来后续互动”，再决定扩展更多文案、复杂周报页面或新成长系统。
