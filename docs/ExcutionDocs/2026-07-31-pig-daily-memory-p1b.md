# 小猪关系记忆与今日相处 P1-B 执行记录

## 1. 阶段结论

P1-B 选择“关系记忆与今日相处”作为小猪商业样板的下一阶段。P1-A 解决小猪会主动动、会按日常节律陪伴的问题；P1-B 让它能够记住用户和它今天实际完成过的事情。

当前代码已经完成，遵照本轮要求未启动应用、服务或安装包，也未执行测试、构建和迁移。因此本记录只代表静态实现完成，不代表运行验收通过。

## 2. 产品原则

- 日用留存和情绪价值优先于商城扩张。
- 首版只在主面板向小猪用户展示，后端契约保留猫狗复用能力。
- 只聚合现有业务记录，不采集键鼠轨迹、窗口内容或额外监控数据。
- 提醒和聊天按真实业务行计数，不受亲密度冷却、每日经验上限或满级影响。
- 点击、拖拽、照料和装扮只统计实际进入亲密度事件的有效动作，不统计被冷却或上限拦截的重复操作。
- 今日摘要不增加经验，不形成签到、惩罚或连续登录压力。

## 3. 数据契约

新增接口：

`GET /api/v1/pets/{pet_type}/daily-summary`

接口按照当前用户、宠物类型和 `PET_REWARD_TIMEZONE` 对本地自然日进行隔离，返回：

- `local_date` 和 `timezone`
- `interaction_count`：今日有效相处总数
- `xp_gained`：今日实际获得的亲密度经验
- `action_counts`：亲密度动作分布
- `care_count`：摸摸、喂食和清洁次数
- `meaningful_chat_count`：该宠物参与的真实用户聊天次数
- `reminders_created_count`：今日创建提醒数
- `reminders_completed_count`：今日完成提醒数
- `first_interaction_at` 和 `last_interaction_at`

总数的来源规则：

1. 普通互动读取 `pet_intimacy_events` 中实际获得奖励的动作。
2. 提醒读取 `reminders` 的创建时间、完成状态和完成时间。
3. 聊天读取 `chat_messages` 中带宠物类型的用户消息。
4. 提醒和聊天不会与对应亲密度奖励事件重复计数。

## 4. 聊天链路补全

- 用户聊天消息新增可空的 `pet_type` 字段。
- 新增 Alembic 迁移 `007_chat_message_pet_type.py`。
- SQLite 旧库启动兼容逻辑会补字段和日统计索引。
- 普通聊天与流式聊天在助手回复保存后，按用户消息 ID 幂等奖励 `meaningful_chat`。
- 奖励失败只记录服务日志，不影响已经完成的聊天回复。

## 5. 桌面表现

主面板在选择小猪时新增无卡片嵌套的“今日相处”区域，显示：

- 今日相处次数
- 已完成提醒数
- 今日获得经验
- 照料、聊天和记下提醒的非零摘要
- 一句由当天事实生成的小猪陪伴文案

主动陪伴事件真正触发时才读取一次今日摘要。读取成功后，小猪优先说出今天完成提醒、被照料、聊天或共同相处的事实；同一类记忆文案当天只使用一次，然后回到原有时段和关系等级文案。接口失败时自动使用 P1-A 原文案，不阻断动作和调度状态。

## 7. 后续运行验收

恢复环境验证后，需要逐项确认：

1. 跨 00:00 后摘要切换到新自然日，且使用配置时区。
2. 不同账号、不同宠物的数据不会混入小猪摘要。
3. 连续聊天即使处于经验冷却期，也会增加真实聊天次数，但经验只按策略增加。
4. 创建提醒和完成提醒各计一次，不与亲密度奖励事件重复。
5. 取消提醒不会计入完成提醒。
6. 主面板登录、切换宠物、聊天、换装和完成提醒后能刷新摘要。
7. 桌宠主动事件能够读取当天事实，接口失败时仍播放原动作和原文案。
8. 迁移 007 能在现有关系表和聊天数据上无损升级与回滚。

## 8. 已知边界

满级后，提醒和聊天仍由真实业务表完整计数；点击、拖拽、照料和装扮仍依赖亲密度奖励事件，因此不会记录满级后不再产生奖励事件的动作。若后续需要长期满级陪伴统计，应在 P1-C 增加与经验系统解耦的宠物活动事件表，而不是放宽冷却或记录原始点击。

## 9. 本阶段非目标

- 跨日、跨周和长期回忆叙事。
- 提醒邮件投递扩展。
- 重复提醒。
- 商城、货币、抽卡或限时装扮。
- 猫狗主面板视觉复刻。
- RTC 续期、移除或重构。
