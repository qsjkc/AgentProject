# 小猪商业化桌宠样板需求文档

**日期：** 2026-07-27

**状态：** 产品需求草案

**范围：** 仅面向桌面端的小猪商业化样板。猫和狗后续基于该样板复刻，不进入本阶段实现范围。

---

## 1. 产品定位

小猪应成为 Detachym 第一个可商业化落地的桌面宠物样板。

目标体验不是简单动画 demo，也不是纯提醒工具，更不是重度虚拟宠物游戏。它应该是一个能长期停留在桌面上的陪伴型伙伴：

- 平时在桌面上有生命感。
- 用户触碰和互动时有情绪反应。
- 长期使用会有明确的关系成长反馈。
- 通过提醒和轻任务能力提供实际日用价值。
- 小猪打磨完成后，可以作为猫和狗的复用模板。

产品核心可以定义为：

> 一个有轻任务价值的桌面情绪陪伴伙伴。

推荐体验权重：

- 情绪留存：50%
- 生命感互动：25%
- 成长和装扮：15%
- 提醒工具价值：10%

RTC 语音链路继续保留在项目中，但不是本阶段主线。

## 2. QQ 宠物参考

QQ 宠物值得参考，是因为它不是单点功能，而是把桌面存在感、宠物成长、照顾行为、小游戏、装扮道具和长期情感连接组合在一起。公开资料中也能看到它包含喂食、清洁、学习、打工、游戏、任务、旅游等养成环节。

本项目应该吸收其中对留存有价值的部分，同时避开会制造压力或导致范围膨胀的部分。

### 2.1 可以借鉴的模式

- 桌面陪伴存在感。
- 日常照顾和互动。
- 明确的成长反馈。
- 装扮和道具解锁。
- 小任务闭环。
- 通过反复接触建立情感连接。

### 2.2 V1 应避免的模式

- 饥饿、疾病、死亡等强惩罚循环。
- 重度虚拟经济系统。
- 付费货币、抽卡、稀有度和商城运营。
- 结婚、生蛋、社交社区或多宠繁育。
- 复杂打工、学习、经济模拟。

- 新华网：https://www.xinhuanet.com/politics/2018-07/11/c_1123107784.htm
- 维基百科：https://zh.wikipedia.org/zh-hans/QQ%E5%AE%A0%E7%89%A9

## 3. 产品原则

### 3.1 日用留存优先

用户应该愿意每天把小猪挂在桌面上。小猪不能只是静态图片，也不能只在提醒触发时出现。

### 3.2 情绪价值先于效率价值

提醒和任务能力很重要，但它们应通过小猪的人格、动作和反馈表达出来。用户感受到的应该是“小猪在帮我”，而不是“提醒应用套了一层宠物皮肤”。

### 3.3 不做惩罚式照顾

可以加入轻量照顾行为，但不能惩罚忙碌用户。V1 不做健康下降、死亡、饥饿惩罚、强制清洁、亲密度下降或掉级。

### 3.4 先做透小猪，再复用到猫狗

小猪是完整模板。后续猫和狗应复用同一套状态机、亲密度数据、提醒流程、装扮库存结构和 UI 概念。不同动物主要差异应集中在视觉资产、装扮适配点、声音和人格文案。

## 4. 目标用户体验

### 4.1 第一次启动

用户第一次打开后的 3 分钟内，应能明确感受到：

- 小猪在桌面上是“活的”。
- 小猪会移动、休息和反应。
- 用户可以直接和它互动。
- 小猪有可见的亲密度等级。
- 小猪能创建并完成提醒闭环。

### 4.2 日常使用

用户正常使用电脑时，小猪应该能：

- 待机时有呼吸或细微身体动作。
- 偶尔走动、伸懒腰、观察周围、坐下或打瞌睡。
- 低活动时进入休息或睡眠状态。
- 被互动时醒来或回应。
- 对点击、摸摸、拖拽、逗弄、喂食、清洁、换装做出反馈。
- 用短气泡表达稳定的人格，不要过度打扰。
- 在有意义互动后增加亲密度。
- 保持提醒能力，但不要让提醒压过陪伴体验。

### 4.3 长期使用

连续使用几天后，用户应该能看到：

- 亲密度等级成长。
- 进度条推进。
- 新装扮或小道具解锁。
- 新动作或待机表现解锁。
- 更亲近的人格文案。
- 更主动但克制的问候和关心。

## 5. P0 商业样板范围

P0 是第一个商业化样板版本，应足够用于日常测试、产品演示，并为后续猫狗复刻提供稳定模板。

### 5.1 生命感动画

P0 必须包含以下动作：

- `idle`：呼吸或细微生命感动作。
- `walk`：短距离桌面走动。
- `jump`：开心跳跃或吸引注意动作。
- `happy`：正向反馈。
- `confused`：没理解或困惑反馈。
- `reminding`：提醒触发状态。
- `sleeping`：低活动或休息状态。
- `wake`：从睡眠中醒来。
- `poke`：点击或戳一戳反应。
- `drag`：被拖拽或移动反应。
- `pat`：被摸摸或安抚反应。
- `eat`：轻量喂食动作。
- `clean`：清洁照顾动作。
- `dress-up`：换装反馈。
- `level-up`：亲密度升级庆祝。

动画要求：

- 小猪样板继续使用透明 PNG 帧。
- 所有帧保持统一画布尺寸和锚点。
- 切换动作时不能造成明显位置跳动。
- 支持动作优先级、中断和回落到待机。
- 动作契约需要可复用到猫和狗。

### 5.2 用户互动

用户应能通过以下方式和小猪互动：

- 点击或戳一戳。
- 拖拽。
- 摸摸或安抚。
- 喂小零食。
- 清洁或擦一擦。
- 换装。
- 从睡觉中叫醒。

每个互动都应包含：

- 一个动画反馈。
- 一句短小猪风格气泡。
- 可选亲密度经验增加。
- 冷却时间，避免刷经验或视觉刷屏。

### 5.3 显性亲密度系统

产品应包含可见的关系成长反馈：

- 显示 `亲密度 Lv.X`。
- 显示亲密度进度条。
- 显示当前进度，例如 `72 / 100`。
- 有意义互动后显示小型 `+N 亲密度` 反馈。
- 达到新等级时触发升级动画和气泡。

系统不应包含：

- 经验扣除。
- 等级下降。
- 饥饿惩罚。
- 死亡或生病。
- 强制每日签到惩罚。

推荐关系阶段：

- Lv.1：刚认识
- Lv.2：有点熟
- Lv.3：会黏人
- Lv.4：老搭档
- Lv.5：特别信任你

具体阶段名称可以在文案阶段调整，但 P0 需要同时支持数字等级和情绪化阶段文本。

### 5.4 成长奖励

每个亲密度等级应混合解锁少量内容：

- 装扮物品。
- 动作或待机变体。
- 小猪专属气泡文案。
- 主动行为。

推荐 P0 奖励结构：

| 等级 | 关系阶段 | 解锁示例 |
| --- | --- | --- |
| Lv.1 | 刚认识 | 基础待机、走动、戳一戳、提醒 |
| Lv.2 | 有点熟 | 小围巾、摸摸反应、问候文案 |
| Lv.3 | 会黏人 | 睡帽、喂食动作、更多待机变体 |
| Lv.4 | 老搭档 | 工作牌、提醒道具、主动关心 |
| Lv.5 | 特别信任你 | 特殊装扮套装、升级庆祝、更亲密文案 |

### 5.5 装扮系统

P0 应包含轻量装扮系统，而不是完整商城。

支持的装扮槽位：

- 头部：帽子、睡帽、小饰品。
- 颈部：围巾、领结、项圈。
- 手持或旁侧道具：铃铛、零食、工作牌、提醒道具。
- 场景道具：提醒或睡眠时临时出现的小道具。

装扮行为：

- 用户可以选择已解锁的基础装扮。
- 当前装扮在重启后保留。
- 场景道具可以临时覆盖或叠加在用户选择的装扮上。
- 睡觉、提醒、升级时可以显示专属小道具。
- 装扮数据按用户和宠物分别保存。

P0 不包含：

- 付费商城。
- 虚拟货币。
- 抽卡。
- 稀有度。
- 限时售卖。

### 5.6 提醒工具价值

现有提醒基础应保留，但 P0 要强化情绪化交付：

- 继续支持自然语言创建提醒。
- 创建提醒时使用小猪人格文案反馈。
- 提醒到点时触发动画、气泡和系统通知。
- 完成提醒后增加亲密度。
- 错过提醒应可见，并能补处理。
- 提醒数据仍按当前激活宠物触发。

P0 可以继续聚焦一次性提醒。重复提醒默认放到 P1，除非演示场景强依赖。

### 5.7 人格文案

小猪人格应保持稳定：

- 柔和、放松、治愈，有一点慢悠悠。
- 温暖，但不要过度讨好。
- 可以有轻微幽默。
- 不能像通用 AI 助手。

文案应按以下场景变化：

- 亲密度等级。
- 用户互动动作。
- 创建提醒。
- 提醒到点。
- 错过提醒。
- 亲密度升级。
- 长时间待机。
- 睡醒。

## 6. P1 增强范围

P1 应在 P0 稳定后深化留存。

推荐 P1 功能：

- 更多待机动作变体。
- 早上、下午、晚上的每日问候。
- 每周完成提醒和互动总结。
- 重复提醒：每天、工作日、每周。
- 装扮解锁页，显示已解锁和未解锁状态。
- 更多照顾行为。
- 更多关系阶段文案。
- 亲密度和装扮的离线缓存与同步冲突处理。
- 用于评估留存的基础埋点。

P1 仍然不应引入重度付费和社交系统。

## 7. P2 后续商业化范围

P2 只有在小猪验证出留存价值后再考虑更大的商业化系统。

可能的 P2 功能：

- 装扮商店。
- 季节装扮包。
- 付费外观套装。
- 节日活动装饰。
- 更复杂的任务助手工作流。
- 多宠物房间或桌面场景。
- 社区或分享能力。
- 猫和狗的商业化复刻。

P2 不应混入 P0 执行计划。

## 8. 数据需求

数据设计应支持现在的小猪，以及后续猫狗复刻。

按用户和宠物分别保存：

- 宠物类型。
- 亲密度等级。
- 亲密度经验。
- 关系阶段。
- 当前心情。
- 当前装扮选择。
- 已解锁装扮物品。
- 互动次数统计。
- 提醒次数统计。
- 最后活跃时间。
- 最后问候时间。
- 最后升级时间。

提醒归属继续保持用户维度和宠物维度。

宠物数据应保持隔离：

- 小猪提醒和小猪亲密度数据与猫、狗分开。
- 只有当前激活宠物触发提醒交付。
- 切换离开有待处理提醒的宠物时，应提示用户。

## 9. 系统模块

推荐模块边界：

- 动画注册表：将宠物类型和动作映射到帧资源及元数据。
- 动画状态机：决定当前动作、优先级、中断和回落。
- 互动控制器：将用户行为映射为动画、文案和亲密度收益。
- 亲密度服务：计算经验、等级、奖励和关系阶段文本。
- 装扮注册表：定义槽位、物品元数据、解锁条件和视觉叠加规则。
- 装扮渲染器：把装扮资源稳定放置到宠物身上。
- 提醒桥接层：把提醒事件连接到动画、气泡、通知和亲密度收益。
- 持久化 API：保存亲密度、装扮和提醒状态。

这些边界都应能复用到猫和狗。

## 10. UI 需求

### 10.1 桌宠表面

桌宠表面应保持轻量：

- 小猪仍然是视觉中心。
- 气泡短小，不打扰。
- 亲密度增加反馈应轻量并短暂出现。
- 装扮变化应立即可见。

### 10.2 主面板

主面板应包含：

- 关系状态区域。
- 等级和进度条。
- 当前关系阶段文本。
- 装扮入口。
- 提醒入口或现有提醒控制。
- 基础宠物状态。

P0 不应把主面板做成重度游戏大厅。

### 10.3 装扮视图

装扮视图应包含：

- 按槽位分组或使用槽位标签。
- 已解锁物品选择。
- 未解锁物品预览和解锁条件。
- 当前已装备状态。
- 恢复默认或清空装扮选项。

## 11. 验收标准

满足以下条件时，P0 可以视为成功：

- 首次用户 3 分钟内能看到小猪移动和反应。
- 用户至少可以通过点击、拖拽、摸摸、喂食、清洁、换装与小猪互动。
- 小猪有可见的 `亲密度 Lv.X`、进度条和当前经验。
- 测试数据中至少可以达到 3 个亲密度等级。
- 至少 1 个装扮物品可以通过亲密度成长解锁。
- 提醒创建、到点交付、完成处理和亲密度增加形成完整闭环。
- 重启应用后，亲密度、装扮和提醒状态都能保留。
- 不存在惩罚式照顾循环。
- 同一套模块契约可以复用到猫和狗。

## 12. 非目标

小猪 P0 明确不包含：

- 浏览器插件。
- RTC 续期、移除或重构。
- 付费商城。
- 抽卡。
- 虚拟货币。
- 社交社区。
- 结婚或繁育。
- 宠物死亡、生病或惩罚。
- 完整 QQ 宠物式虚拟社区。
- 多宠物同时显示在桌面。

## 13. 执行计划拆分建议

进入实现前，应单独创建执行计划，并拆成以下工作：

1. 数据模型和持久化。
2. 亲密度系统。
3. 装扮注册表和存储。
4. 装扮渲染和资源锚点规则。
5. 互动控制器。
6. 小猪动作和照顾动画扩展。
7. 提醒情绪化交付优化。
8. 主面板 UI 更新。
9. 桌面端测试覆盖。
10. 猫狗复刻检查清单。

第一次实现仍应坚持小猪优先。猫和狗应等小猪契约验证后再进入实现。

## 14. 已确认产品决策

以下决策作为后续执行计划的默认输入，不再作为开放问题处理。

### 14.1 亲密度等级曲线

P0 使用 5 个等级，采用累计经验阈值：

| 等级 | 关系阶段 | 累计亲密度经验 |
| --- | --- | --- |
| Lv.1 | 刚认识 | 0 |
| Lv.2 | 有点熟 | 100 |
| Lv.3 | 会黏人 | 260 |
| Lv.4 | 老搭档 | 520 |
| Lv.5 | 特别信任你 | 900 |

UI 展示当前等级内进度，例如 Lv.2 时展示 `45 / 160`，其中 160 是从 Lv.2 升到 Lv.3 所需经验。

设计意图：

- Lv.2 应在首日轻度体验中可达。
- Lv.3 应在连续使用几天后可达。
- Lv.4 和 Lv.5 保留长期留存空间。
- P0 不设置 Lv.5 之后的无限成长，后续版本再扩展。

### 14.2 互动经验奖励

亲密度只增加不扣减。所有奖励都需要冷却或每日上限，避免刷经验。

| 行为 | 经验奖励 | 冷却/上限建议 |
| --- | --- | --- |
| 每日首次启动或唤醒 | +5 | 每天 1 次 |
| 点击或戳一戳 | +1 | 60 秒冷却，每天最多 +20 |
| 拖拽后放下 | +1 | 60 秒冷却，每天最多 +10 |
| 摸摸或安抚 | +3 | 5 分钟冷却，每天最多 +30 |
| 喂小零食 | +5 | 30 分钟冷却，每天最多 +20 |
| 清洁或擦一擦 | +4 | 30 分钟冷却，每天最多 +16 |
| 换装成功 | +3 | 10 分钟冷却，每天最多 +12 |
| 创建提醒 | +4 | 每天最多 +20 |
| 完成提醒 | +10 | 每天最多 +50 |
| 有意义聊天回应 | +2 | 5 分钟冷却，每天最多 +20 |

P0 每日亲密度总收益建议限制在 120 以内。这样用户能看到进度，但不会一天刷满所有等级。

### 14.3 第一批装扮集合和解锁顺序

P0 使用轻量装扮集合，先覆盖头部、颈部、侧边道具和场景道具。

| 解锁条件 | 物品 | 槽位 | 目的 |
| --- | --- | --- | --- |
| 默认解锁 | 基础小围巾 | 颈部 | 让用户首次进入装扮页就能立即试穿 |
| Lv.2 | 睡帽 | 头部 | 强化睡觉、打瞌睡场景 |
| Lv.3 | 小铃铛 | 侧边道具 | 强化提醒到点场景 |
| Lv.4 | 小工作牌 | 颈部/侧边道具 | 强化任务伙伴感 |
| Lv.5 | 星星小帽 | 头部 | 作为第一阶段长期奖励 |

场景道具不一定全部需要用户手动装备。比如提醒时的小铃铛、睡觉时的睡帽，可以在对应动作中临时叠加；如果用户已解锁，则优先使用已解锁版本。

### 14.4 重复提醒范围

P0 不做重复提醒，只保留一次性提醒。

原因：

- 当前核心目标是小猪商业样板的情绪留存和生命感互动。
- 重复提醒会引入规则编辑、跳过、延期、周期冲突等复杂度。
- 一次性提醒已经足够验证“小猪创建提醒、到点提醒、完成后增加亲密度”的闭环。

重复提醒进入 P1，优先级顺序为：

1. 每天。
2. 工作日。
3. 每周。

### 14.5 装扮资产方案

P0 默认使用独立叠加 PNG，而不是为每个动作预合成完整图片。

执行规则：

- 每个装扮物品提供透明 PNG。
- 每个宠物动作定义锚点元数据。
- 必要时可按动作定义细分锚点，例如 `sleeping.head`、`reminding.sideProp`。
- 装扮渲染器根据当前动作、帧序号和槽位锚点叠加装扮。
- 换动物时复用同一槽位语义，但使用对应动物的锚点配置。

允许例外：

- `level-up` 这类强表现动作可以使用预合成特效帧。
- 如果某个动作变形太大，导致叠加 PNG 明显穿帮，可以为该动作提供专用装扮帧。

默认不使用全量预合成，因为那会让每个装扮乘以每个动作，后续猫狗复刻和装扮扩展成本会失控。

### 14.6 亲密度和装扮同步策略

P0 采用“后端为准 + 本地缓存”的策略。

具体规则：

- 后端保存用户维度、宠物维度的亲密度、等级、已解锁装扮和当前装备。
- 桌面端使用 `electron-store` 保存最近一次成功同步的关系状态和装扮状态。
- 在线时，亲密度和装扮变化应尽快同步到后端。
- 短暂离线时，桌面端可以先本地记录变更队列，恢复联网后补同步。
- 冲突处理以服务端时间更新较新的记录为准；同一字段本地更新失败时应回滚或提示重试。

这个策略比纯本地存储更适合商业化，也能为后续多端登录和猫狗复刻保留空间。
