# 小猪周回顾最小留存埋点 P1-G 执行记录

## 1. 阶段结论

P1-G 为 P1-F 周回顾增加专用、白名单、隐私最小化的留存漏斗事件，用于回答“周回顾是否生成、是否展示、是否成功已读，以及展示后用户是否继续照料、聊天或使用提醒”。

本阶段没有引入第三方分析 SDK、任意客户端事件、聊天原文、提醒标题、设备指纹或复杂用户画像。当前代码、自动化测试、桌面渲染构建和迁移 012 隔离验证已经完成；尚未在真实桌面运行、现有 PostgreSQL 或生产数据上验收。

## 2. 事件契约

系统只允许以下事件：

- `weekly_review_generated`
- `weekly_review_shown`
- `weekly_review_seen`
- `weekly_review_follow_up_care`
- `weekly_review_follow_up_chat`
- `weekly_review_follow_up_reminder`

每条事件只保存：

- 内部用户 ID。
- 宠物类型。
- 白名单事件类型。
- 周回顾 `review_key`。
- 服务端事件时间。

数据表不包含任意 metadata、客户端时间、聊天内容、提醒标题、提醒来源文本、文案内容、IP、设备 ID 或广告标识。

## 3. 漏斗语义

- 有资格展示的完整周回顾首次查询时记录 `generated`。
- 桌面端真正显示周回顾气泡后，best-effort 上报 `shown`。
- 已读回执成功写入服务端后记录 `seen`。
- 已读后 7 天内发生照料、有效聊天、创建提醒或完成提醒时，记录对应后续行为类别。
- 同一用户、宠物、周和事件类型最多保留一条记录；重复查询、重复展示上报、冷却期操作和请求重试不会放大漏斗计数。
- 空白周不生成事件，已读前行为和超过 7 天窗口的行为不计为周回顾后续行为。

## 4. 稳定性边界

留存事件是辅助观测，不得阻断核心体验：

- 桌面端展示上报不等待完成，不阻塞已读回执或本地陪伴状态落盘。
- 服务端埋点写入失败时回滚埋点事务并记录最小错误上下文，不让周回顾、亲密度、聊天或提醒主流程失败。
- 唯一约束处理并发重复事件，服务层也在写入前做幂等检查。

新增接口：

- `POST /api/v1/pets/{pet_type}/weekly-summary/shown`

接口继续使用当前用户认证和严格的 `review_key` 格式，只接受当前可用且有内容的周回顾。

## 5. 数据库迁移

迁移 012 新增 `pet_retention_events`：

- 外键随用户删除而级联清理。
- 检查约束限制六类事件。
- 唯一约束锁定每个漏斗步骤的幂等性。
- `event_type + occurred_at` 索引用于后续按时间聚合。

## 6. Review 修复

本轮 review 和测试发现并修复：

1. 初次补丁误命中结构相似的日总结返回块，导致日总结返回 `None`；已恢复日总结原有行为并重新完成针对性、全量回归。

3. 增加空白周、事件白名单、7 天窗口、重复展示、冷却期重复行为和用户/宠物/周隔离测试。

## 9. 下一阶段建议

P1-H 建议增加管理员只读的聚合漏斗：按周和宠物返回生成、展示、已读、后续互动用户数及转化率，不返回原始用户 ID 或单用户事件。先让当前埋点能够被安全解释，再决定是否扩展周回顾文案或交互。
